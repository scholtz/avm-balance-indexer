# 0022 .NET 11 as the runtime and SDK

Status: accepted (issue #216).

## Context
The solution ran on .NET 10 (LTS). .NET 11 is generally available (SDK 11.0.100, packages 11.0.0) and the owner asked to move to it together with the latest version of every package.

## Decision
- `global.json` pins SDK 11.0.100 (`rollForward: latestFeature`), every project targets `net11.0`, the Docker images are `dotnet/sdk|aspnet|runtime:11.0`. A machine needs the 11 SDK (README, CONTRIBUTING); CI installs it through `global-json-file`.
- The client SDK for .NET keeps `net8.0;net10.0`, so consumers are not forced up. Its CI jobs install those runtimes next to the 11 SDK; the job that runs `sdk/scripts/generate.sh` keeps an older runtime for NSwag.
- `Microsoft.Extensions.*` packages that .NET 11 ships in the framework are not referenced any more (NU1510 is an error): the projects cannot be retargeted to an older framework without adding them again.
- Packages without a stable 11.x line (Serilog, Npgsql, OpenTelemetry, Cassandra driver) stay at their latest stable version.

## Consequences
- .NET 11 is a standard-term-support release: plan the next move (the next LTS, .NET 12) within its support window; Dependabot proposes the image and SDK bumps.
- The OpenAPI library of .NET 11 writes the tags alphabetically; the committed document follows it (SDK 1.3.2, no generated code change).
